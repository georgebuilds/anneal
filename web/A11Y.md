# anneal studio accessibility checklist

Status: binding. This is the gate every web view (W0 foundation, W1+ feature
views) ships through. If your view does not pass every item below, it does not
ship. Cross-refs: `DESIGN.md §11`, `notes/anneal_web_spec.md §10`.

No em-dashes anywhere in this doc, per project convention.

---

## §0. What this doc is

`A11Y.md` is the operational form of `DESIGN.md §11` (the binding a11y
invariants). DESIGN says what; A11Y says how to verify it. When a new view
lands, the PR description quotes the checklist below and marks each item.

The hard constraint, from George: "the web stuff should be as accessible as
possible." Read: WCAG 2.2 Level AA across every surface, with AAA where it is
cheap (touch target size, link/button distinction, focus indicator
strength). The W0 foundation bakes this in so every subsequent view inherits
the discipline; do not break the foundation when adding W1+ content.

---

## §1. Per-view checklist

Copy this list into the PR description for each new view. Every box must be
checked before merge.

- [ ] **Heading hierarchy.** The active view exposes exactly one `<h1>`
  (others may be `visually-hidden` if the view chrome already names the
  surface). Inactive `.view` sections are `display:none`, so their `<h1>`
  elements are hidden from the a11y tree. No `<h3>` before `<h2>`.
- [ ] **Landmarks present.** Page has `<header role="banner">`,
  `<nav role="navigation" aria-label>`, `<main role="main" id="main">`,
  and `<footer role="contentinfo">`. New view content lives inside `<main>`.
- [ ] **Skip link** is the first focusable element and lands on `#main`.
- [ ] **Focus visible.** Every interactive element shows a focus ring via
  the global `:focus-visible` rule. Do not write `outline: none` without a
  replacement. The studio's focus token is `--focus-ring` (gold).
- [ ] **Focus order matches DOM order.** No `tabindex` greater than 0.
  `tabindex="-1"` is allowed for programmatically-focused targets like
  `<main>` itself.
- [ ] **Keyboard reachable.** Every interactive control is reachable by Tab
  and operable by Enter / Space (buttons) or normal text input (inputs).
  No mouse-only affordances.
- [ ] **No keyboard traps.** Focus can always escape every container. The
  keyboard-help modal traps Tab within it but Escape always exits.
- [ ] **ARIA labels.** Every icon-only button has an `aria-label` that
  describes the action ("close keyboard shortcuts", not "X"). Decorative
  SVGs have `aria-hidden="true"` and `focusable="false"`.
- [ ] **Color contrast.** Body text >= 4.5:1 on its background. UI
  component borders, focus indicators, and large text >= 3:1. The
  brand-token verification lives in `cmd/anneal/cmd_web_test.go`
  (`TestWebA11Y_BrandTokenContrast`); a new background or text token added
  to `studio.css` must be added to that test.
- [ ] **DD1: color is never alone.** Any place that uses teal / ember /
  gold for meaning pairs the color with shape, label, or weight. The
  active nav state is teal + left border + font weight bump.
- [ ] **Live region updates.** SPA route change announces "navigated to
  {view}" via `#live-region`. SSE-driven views (W5 train, W6 generate)
  announce new events the same way (`announce()` in `studio.js`).
- [ ] **Document title** updates on view change. Format:
  `anneal · {view}`.
- [ ] **`lang="en"` on `<html>`** is intact. If your view introduces non-
  English content (e.g. a code identifier in a non-Latin script), mark it
  with `lang` on the element.
- [ ] **Touch target 44x44.** Every clickable element meets the minimum
  hit area (WCAG 2.5.5 AAA). Verify with the dev-tools accessibility
  pane.
- [ ] **Text resize.** Layout works at 200% browser zoom with no
  horizontal scroll. Type sizes use `rem`, not `px`. Verify by zooming.
- [ ] **Reduced motion.** Every animation site checks
  `@media (prefers-reduced-motion: reduce)` and disables or shortens. The
  global `*` rule in `studio.css` is the backstop; per-animation rules
  are the belt.
- [ ] **Forced colors.** Critical UI (nav active state, focus ring, links)
  is verified in Windows High Contrast mode. CSS uses system color
  keywords (CanvasText, Highlight, LinkText) in the `forced-colors:
  active` block.
- [ ] **Prefers contrast: more.** A high-contrast theme variant exists
  (sharper borders, less transparency). See the `prefers-contrast: more`
  block in `studio.css`.
- [ ] **Screen-reader landmark sweep.** With VoiceOver (or NVDA / orca)
  open, the page's landmark menu lists banner, primary navigation, main,
  contentinfo. Each lands on the right region.
- [ ] **No color-only meaning.** If your view introduces a chip, pill, or
  badge, the meaning is in the text label too (e.g. status pill says
  "done" or "cancelled", not just colour).

## §2. Verification recipes

### §2.1 Lighthouse

```
# In Chrome devtools → Lighthouse → Accessibility, run against the live
# `anneal web` server. Target: 100/100. The 99 we typically see is the
# tap-target audit on monochrome-by-design chips, which is not a real
# failure but flag it in the PR.
anneal web :3001
# open http://localhost:3001/, devtools, Lighthouse, Accessibility.
```

### §2.2 axe-core (optional, no project dep)

Run from the devtools console with axe loaded from the user's own
extension (we do not ship a dep). Zero serious or critical violations is
the gate.

### §2.3 Manual keyboard sweep

1. Reload the page. The first Tab lands on the skip link.
2. Tab through every element. Focus must always be visible.
3. Press `?`. The keyboard-help modal opens. Focus moves to the close
   button.
4. Tab inside the modal. Focus stays inside (focus trap).
5. Press Escape. Modal closes. Focus returns to the trigger.
6. Press `g v` (chord). Visualize view loads. Title and live region
   update.
7. Press `/`. Search input is focused.
8. Press Escape. Search input is blurred.

### §2.4 Manual screen-reader sweep

- **macOS VoiceOver.** Cmd-F5 to enable; use the rotor (VO-U) to list
  landmarks. Expect: banner, navigation (2: primary, breadcrumb), main,
  contentinfo. Navigate to each. Then enable the headings rotor: expect
  exactly one h1 in the rendered view.
- **Linux orca / Windows NVDA.** Same expectations. Press Insert+F7
  (NVDA) for the elements list. Landmarks tab should show the four.

### §2.5 Reduced motion + forced colors

- macOS: System Settings → Accessibility → Display → Reduce motion.
  Reload the page; the wordmark must not animate.
- Windows: Settings → Accessibility → Contrast themes → "Aquatic" or
  similar forced theme. The studio's borders, focus rings, and nav
  active state must still read.

### §2.6 200% zoom

In Chrome devtools, set viewport to 100% then press Cmd-+ until zoom is
200%. Verify:
- No horizontal scroll.
- Nav rail collapses to a top section (covered by the `@media
  (max-width: 720px)` block in `studio.css`).
- All text remains readable.

## §3. Verified brand-token contrast (W0 baseline)

Computed against the dark `--bg #14110F` and light `--bg #FBF8F3`
backgrounds, plus the `--surface` panel backgrounds. WCAG 2.2 Level AA
requires 4.5:1 for normal text, 3:1 for large text and UI components.

| token / theme        | hex      | on bg       | on surface  | verdict          |
|----------------------|----------|-------------|-------------|------------------|
| dark text            | #E8E2DA  | 14.61:1     | 13.40:1     | AAA              |
| dark muted           | #8A817A  | 4.93:1      | 4.52:1      | AA (text)        |
| dark faint           | #5C544D  | 2.53:1      | 2.32:1      | UI / dividers only |
| dark teal (forward)  | #00ADD8  | 7.14:1      | 6.54:1      | AAA on bg        |
| dark ember (back)    | #FF7A45  | 7.27:1      | 6.67:1      | AAA on bg        |
| dark gold (fused)    | #F2C57C  | 11.69:1     | 10.71:1     | AAA              |
| light text           | #14110F  | 17.75:1     | 15.55:1     | AAA              |
| light muted          | #5C544D  | 7.00:1      | 6.14:1      | AA               |
| light faint          | #8A817A  | 3.60:1      | 3.16:1      | UI / large-text only |
| light teal (forward) | #006F9E  | 5.26:1      | 4.61:1      | AA               |
| light ember (back)   | #B84A16  | 4.92:1      | 4.31:1      | AA on bg; UI on surface |
| light gold (fused)   | #7A5800  | 6.15:1      | 5.39:1      | AA               |

Notes:

- `--faint` (gray-on-gray) is dividers and decorative hint chips only.
  It is below 4.5:1 by design; it must never carry text meaning.
- `--ember` on the light `--surface` is 4.31:1 (under the 4.5 floor by
  0.19). Ember on surface is used as a chip border in the light theme,
  not as body text. If a future view places ember body text on the
  light surface, switch to ember-on-bg (4.92:1) or darken to `#A3400F`.
- The test `TestWebA11Y_BrandTokenContrast` in
  `cmd/anneal/cmd_web_test.go` recomputes these at build time. If a
  failing ratio appears for a token used as body text, the test STOPS
  the build. Do not edit the token to silence the test; report to
  George and let the brand-token semantics get a deliberate update.

## §3a. W2 a11y verification (kernels view)

Phase: W2 kernels view (`/k/<model>`). Verified items below; manual checks
documented as MANUAL where Go-side source-text checks don't cover them.
The W2 test set lives in `cmd/anneal/cmd_web_kernels_test.go`
(10 tests) and `cmd/anneal/cmd_kernels_test.go` (5 tests).

- [x] **Heading hierarchy.** One `<h1 id="view-kernels-heading">` per the
  view; covered by the existing `TestWebA11Y_HeadingHierarchy` sweep
  which counts h1 per `.view` section. No `<h2>` precedes `<h1>` in the
  kernels view.
- [x] **Landmarks present.** No new landmarks introduced; the kernel list
  uses an `<aside aria-label="kernel list">` inside the kernels-view
  section to scope the assistive label, not as a top-level landmark.
- [x] **Skip link.** Inherited from foundation; unchanged.
- [x] **Focus visible.** Inherited; the list items, the diff toggle, and
  the WGSL `<pre>` all rely on the global `:focus-visible` rule.
- [x] **Focus order matches DOM order.** Rail → search → topbar → kernel
  list → kernel detail (header → diff toggle → WGSL pre). Tab through
  in source order. (MANUAL spot-check; no programmatic tabindex >= 0
  introduced.)
- [x] **Keyboard reachable.** The kernel list is a real `<ul
  role="listbox" tabindex="0">`; ArrowDown / ArrowUp / Home / End move
  selection; Enter / Space activate; Escape returns focus to the
  kernels nav rail item. Pinned by `TestWebKernels_KeyboardNav`.
- [x] **No keyboard traps.** Escape on the list returns focus to the nav
  rail. The WGSL `<pre>` is keyboard-scrollable (tabindex=0) and Tab
  exits cleanly to the next interactive element.
- [x] **ARIA labels.** The kernel list has `aria-label="kernels in this
  model"`; the WGSL pre has `aria-label="WGSL source"`; the diff
  toggle has `aria-label` describing the not-yet-wired state. Pinned
  by `TestWebKernels_WGSLPreLabeled` and `TestWebKernels_DiffToggleAriaPressed`.
- [x] **Color contrast.** Token classes use brand vars (`--teal`,
  `--ember`, `--gold`, `--muted`, `--text`); brand-token contrast
  ratios are covered by `TestWebA11Y_BrandTokenContrast`. The
  `--muted` token (used for `.tk-comment` and the gutter "fused"
  carries the documented 4.5+:1 ratio on both bg and surface.
- [x] **DD1: color is never alone.** Tokenizer spans pair colour with
  weight or style: `.tk-keyword { font-weight: 600 }`, `.tk-type {
  font-style: italic }`, `.tk-comment { font-style: italic }`,
  `.tk-attribute { font-weight: 600 }`. The active list item pairs
  the gold left border with a font-weight bump. Pinned by
  `TestWebKernels_TokenizerSpanClasses`.
- [x] **Live region updates.** Kernel selection writes "kernel K3
  selected" to `#live-region` via `announce()`. The "tuned vs
  default" toggle announces "tuned compile pending" today (the
  backend is in W6+). Both go through the same `announce()` channel
  as foundation route changes.
- [x] **Document title.** Inherited from foundation; the route change
  to `/k/<model>` already writes `anneal · kernels`.
- [x] **`aria-current="page"`** on the active nav button. Inherited.
- [x] **`aria-selected`** on the active kernel list item. Set by
  `drawKernelList`. The listbox's `aria-activedescendant` tracks the
  active item by id so screen-reader users hear which option is
  current without focus moving inside the list.
- [x] **Touch target 44x44.** The `.kernel-list-item` and the
  `.diff-toggle` carry `min-height: 44px`; the WGSL pre is a
  scrollable region (no tap target).
- [x] **Text resize.** All sizes are `rem`; the kernels-pane grid
  collapses to a single column under 720px via `@media (max-width:
  720px)`. MANUAL: verified the kernels view at 200% zoom in a real
  browser before landing.
- [x] **Reduced motion.** No animation is introduced in the kernels
  view; the kernel-list item / diff toggle CSS includes a
  `transition: none !important` under `prefers-reduced-motion: reduce`
  as belt-and-braces. The gutter and tokenizer spans never animate.
- [x] **Forced colors.** The tokenizer span colours collapse to
  `CanvasText` under `forced-colors: active`; the weight / italic
  axes carry the distinction (so a screen at high contrast still
  reads "keywords vs comments"). The gutter labels (fwd/bwd/fused)
  fall back to `CanvasText` too; the line-aligned position keeps the
  span structure legible.
- [x] **Prefers contrast: more.** Inherited; the kernels view does not
  introduce its own colour decisions outside the brand tokens, so the
  foundation's `prefers-contrast: more` rule lights up the same way.

DEFERRED / MANUAL:

- Lighthouse + axe-core run on `/k/mlp` is a manual gate before W3 lands;
  the source-text checks above cover the structural contract. The wasm
  artifact must be built first for the real WGSL to render; otherwise the
  pane shows the "wasm not loaded" hint and the live region announces it.
- VoiceOver landmark sweep on `/k/mlp` is a manual gate before W3 lands.
  Expectation: banner, navigation (primary + breadcrumb), main,
  contentinfo. The kernel-list `<aside aria-label="kernel list">` is NOT
  a landmark (aside without `role="complementary"` and inside a section
  reads as a generic group), which is the intended behaviour.
